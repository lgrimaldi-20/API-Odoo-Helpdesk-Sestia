1. Introduccion

Que es API-Odoo Middleware?

API-Odoo es un middleware universal desarrollado en Python con FastAPI que actua como puente entre el ERP Odoo y cualquier sistema externo (agentes de IA, hojas de calculo, scripts, bases de datos, aplicaciones web).

Problema que Resuelve

Odoo utiliza el protocolo JSON-RPC para comunicaciones, que es complejo de implementar directamente. Este middleware simplifica la integracion exponiendo una API REST estandar.

Beneficios Clave

🔌

Un solo endpoint POST para todas las operaciones con Odoo

🔒

🏢

⚡

Rate Limiting

Proteccion contra abuso: 60 req/min por IP

7. Seguridad

Capas de Seguridad

Cada peticion pasa por multiples capas de validacion antes de llegar a Odoo:

1
Rate Limiting
Maximo 60 peticiones por minuto por IP
429
2
API Key
Validacion del token en header X-Api-Key
401
3
Whitelist Modelo
Solo modelos autorizados en ALLOWED_MODELS
422
4
Whitelist Metodo
Solo metodos autorizados en ALLOWED_METHODS
422
5
Logging
Registro de la operacion con timestamp ISO
--
6
Odoo
Ejecucion de la operacion en el ERP
503/422

Detalle de Mecanismos

MecanismoDescripcionConfiguracion
API KeyToken en header X-Api-KeyVariable API_KEY en .env
Whitelist modelosSolo modelos autorizadosVariable ALLOWED_MODELS en .env
Whitelist metodosSolo metodos autorizadosVariable ALLOWED_METHODS en .env
Rate Limiting60 peticiones/min por IPConfigurado en api.py via slowapi
LoggingRegistro de cada peticionLogs con formato ISO
Timeout30 segundos maximo a OdooConfigurado en odoo_universal.py
Buenas Practicas Nunca subir .env al repositorio. Siempre usar HTTPS en produccion. Rotar la API Key periodicamente. Limitar modelos y metodos al minimo necesario.

Cliente Python Reutilizable

pythonimport requests

class OdooClient:
    def __init__(self, url, api_key):
        self.url = url
        self.headers = {
            "Content-Type": "application/json",
            "X-Api-Key": api_key
        }

    def _call(self, model, method, args=None, kwargs=None):
        payload = {
            "model": model,
            "method": method,
            "args": args or [],
            "kwargs": kwargs or {}
        }
        resp = requests.post(self.url, json=payload, headers=self.headers)
        resp.raise_for_status()
        return resp.json()["result"]

    def search_read(self, model, domain=None, fields=None, limit=100):
        return self._call(model, "search_read",
            args=[domain or []],
            kwargs={"fields": fields or [], "limit": limit})

    def create(self, model, values):
        return self._call(model, "create", args=[values])

    def write(self, model, ids, values):
        return self._call(model, "write", args=[ids, values])

    def unlink(self, model, ids):
        return self._call(model, "unlink", args=[ids])

# Uso:
client = OdooClient("https://tu-servidor:8000/odoo", "tu-api-key")
clientes = client.search_read("res.partner",
    domain=[["customer_rank", ">", 0]],
    fields=["name", "email"],
    limit=10)

12. Manejo de Errores

Codigos de Respuesta HTTP

CodigoSignificadoCausaAccion
200 Exito Operacion completada correctamente Procesar campo result
400 Bad Request Tenant no configurado Verificar campo tenant
401 Unauthorized API Key falta o es incorrecta Verificar header X-Api-Key
422 Unprocessable Modelo/metodo no permitido o error Odoo Revisar whitelist y parametros
429 Too Many Requests Excedio 60 req/min Esperar y reintentar con backoff
503 Service Unavailable Odoo no accesible Verificar conexion a Odoo
500 Internal Error Error inesperado del middleware Reportar al equipo

Formato de Error

json{
  "detail": "Descripcion del error en texto legible"
}

Patron de Reintento Recomendado

pythonimport time

def call_with_retry(payload, max_retries=3):
    for attempt in range(max_retries):
        response = requests.post(API_URL, json=payload, headers=headers)

        if response.status_code == 200:
            return response.json()["result"]

        if response.status_code == 429:  # Rate limit
            wait = 2 ** attempt  # Backoff exponencial: 1s, 2s, 4s
            time.sleep(wait)
            continue

        if response.status_code == 503:  # Odoo no disponible
            time.sleep(5)
            continue

        # Otros errores: no reintentar
        response.raise_for_status()

    raise Exception("Maximo de reintentos alcanzado")

14. FAQ - Preguntas Frecuentes

Conexion y Autenticacion

Como obtengo mi API Key?

El administrador la genera con python -c "import secrets; print(secrets.token_hex(32))" y la configura en el .env.

Puedo usar el middleware sin API Key?

Si, en modo desarrollo. Si API_KEY esta vacia en .env, no se requiere autenticacion. Nunca hacer esto en produccion.

Soporta multiples instancias de Odoo?

Si, mediante el campo tenant en cada peticion. Cada tenant tiene sus propias credenciales.

Datos y Modelos

Como se que campos tiene un modelo?

Usar el metodo fields_get:

{"model": "res.partner", "method": "fields_get", "kwargs": {"attributes": ["string", "type"]}}
Puedo acceder a modelos que no estan en la whitelist?

No. Se recibira un error 422. Contactar al administrador para agregar el modelo.

Hay limite de registros por consulta?

Use el parametro limit en kwargs. Se recomienda no superar 500 registros por peticion.

Errores Comunes

Error 503 - Service Unavailable

El middleware no puede conectar con Odoo. Verificar que la URL es correcta y que el servicio esta activo.

Error 429 - Too Many Requests

Se excedio el limite de 60 peticiones por minuto. Implementar backoff exponencial en el cliente.

Error 422 - "modelo no permitido"

El modelo solicitado no esta en la whitelist. Verificar ALLOWED_MODELS en .env.

15. Checklist de Integracion

Antes de poner una integracion en produccion, verificar:

  • URL del middleware es correcta y accesible via HTTPS
  • API Key esta configurada y funciona
  • Endpoint /health responde {"status": "ok"}
  • Los modelos necesarios estan en la whitelist
  • Los metodos necesarios estan en la whitelist
  • Las consultas de lectura (search_read) funcionan correctamente
  • Las operaciones de escritura (create, write) funcionan si son necesarias
  • Se implemento manejo de errores para todos los codigos HTTP
  • Se implemento patron de reintento con backoff exponencial
  • El rate limiting (60 req/min) es suficiente para el caso de uso
  • Los logs del middleware se monitorean
  • Se tiene un plan de contingencia si Odoo no esta disponible
  • La API Key no esta hardcodeada en el codigo fuente
